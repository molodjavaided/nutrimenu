# План работ NutriMenu (июль–сентябрь 2026) — для выполнения агентом (Opus/Fable)

> Основание: `docs/REPORT_2026-07-14.md`. Промпт-техники: `docs/FABLE5_GUIDE.md`.
> Правило: один этап = одна сессия агента. Каждый этап заканчивается `tsc` + тестами + записью в auto-memory.

---

## Как ставить задачи агенту (из гайда Fable 5)

- Давать этап целиком, а не по кусочку: модель сильна на сложных, хорошо описанных задачах.
- В каждый промпт: **зачем** («работаю над X для владельцев кафе, им нужно Y — с учётом этого: …»).
- Требовать честный прогресс: «Перед отчётом сверь каждое утверждение с результатом инструмента; если не проверено — скажи прямо».
- Границы: «Не добавляй функции и рефакторинг сверх задачи; проверяй только на границах системы».
- Проверку выносить свежему субагенту (код-ревью чужим контекстом), не самокритикой.
- CLAUDE.md уже содержит анти-переусложнение — дублировать не нужно; добавить туда блок «честный прогресс» (см. Этап 0).

## Этап 0 — Гигиена (0,5 дня, low-risk)

1. В CLAUDE.md добавить блок «Честный прогресс» из FABLE5_GUIDE (раздел 07.1).
2. `graphify-out/` → .gitignore + удалить из индекса.
3. Удалить `app/(auth)/login`, `app/(auth)/register`, `lib/credentialsStore.ts` (проверить `grep -r credentialsStore` перед удалением).
4. Выровнять TTL: JWT `setExpirationTime('14d')` = `SESSION_MAX_AGE`.
5. `items/route.ts`: добавить `bonusAiEnriches` в выборку и вызов `getEffectiveLimits`.

**Готово когда:** tsc чист, grep не находит ссылок на удалённое, логин работает (/qa золотой путь).

## Этап 1 — Оплата ЮKassa (3–5 дней) 🔴 приоритет

1. Регистрация магазина ЮKassa (ручной шаг Юры — ключи в .env).
2. Модель `Payment` (аддитивная миграция): id, userId, plan, amount, status, yookassaId, createdAt.
3. `POST /api/billing/checkout` — создать платёж, вернуть confirmation_url.
4. `POST /api/billing/webhook` — проверка подписи/IP, идемпотентность по yookassaId, `payment.succeeded` → `plan` + `paidUntil += 30д` в транзакции.
5. UI: кнопка оплаты в `PaywallStep` (закрыть TODO), баннеры trial/awaiting_plan/grace ведут на checkout.
6. Тесты: webhook (подпись, идемпотентность, продление), состояния getUserState после оплаты.

**Готово когда:** тестовый платёж в песочнице ЮKassa проходит цикл checkout → webhook → меню опубликовано.

## Этап 2 — Email (0,5 дня + ручной шаг)

1. Купить домен (ручной шаг Юры), DKIM/SPF в Resend.
2. Проверить forgot-password end-to-end; письмо при APPROVED (код из бэклога, `app/api/admin/venues/[id]/route.ts`).

## Этап 3 — Валидация мутирующих роутов (2–3 дня)

1. zod-схемы для `composition`, `variantGroups`, `modifierGroups`, `sizes` (типы уже в `types/index.ts`) + лимиты размеров (напр. ≤100 ингредиентов, ≤20 групп).
2. Применить в `items` POST/PATCH, `ingredients` POST/PATCH, `categories`. Единый формат ошибок.
3. Незнакомые поля отбрасывать (`.strip()`), не 500-ить.
4. Тесты на отказ мусорных payload'ов.

**Осторожно:** не сломать существующие блюда — схема должна принимать всё, что реально лежит в БД (сначала прогнать выборку прод-данных через схему в dry-run скрипте).

## Этап 4 — Маркетинг-фичи к 1 сентября (параллельно с 1–3)

1. **Комплаенс-страница** — печатная версия меню с КБЖУ (`/menu/[slug]/print`), кнопка в дашборде. Продающий крючок под ПП № 1820.
2. **Бейджи блюд** (веган/острое/без глютена/хит): поле `badges String[]` в MenuItem, чипы в DishCard/форме.
3. **Лендинг «Новые правила с 1 сентября»** + чек-лист PDF за email (лиды в Telegram-бот админа).
4. Блог-раздел: 2 SEO-статьи («калорийность в меню: закон 2026», «QR-меню с КБЖУ»).

## Этап 5 — Техдолг и перфоманс (после первых оплат)

1. `DishSheetContent` отвязать от `lib/store.ts`; демо — на `demo-data`; слить mock/demo-данные.
2. Домиграция `/dashboard/*` на TanStack Query (DashboardClient, IngredientsClient, SettingsClient).
3. View-counter → Redis-инкремент + cron-сброс в Postgres (когда >10 заведений).
4. Распил `lib/importer.ts` и `IngredientsClient.tsx` — только при следующей правке этих файлов, не отдельной задачей.
5. API-тесты: auth, лимиты тарифов, гейты AI (самые денежные пути).

## Этап 6 — Рост (Q4, после 3+ платящих)

Мультиточка (Venue 1:N User — потребует Plan-агента и миграции), брендирование, экспорт ТТК PDF по ГОСТ, iiko-синк (только после Этапа 3), каталог `/venues`.

## Порядок и зависимости

```
Этап 0 → Этап 1 (оплата) → Этап 2 (email) → Этап 3 (валидация) → Этап 5
                 ↘ Этап 4 (маркетинг, параллельно, дедлайн 01.09) ↗      → Этап 6
```

Не запускать платную рекламу до конца Этапа 1. Этап 6 — только после первых платящих клиентов.
