## 1. Приёмы и практики (не скиллы — образ работы)

### 🟢 wrap-session — ритуал закрытия сессии
В конце каждой сессии агент записывает: итог, принятые решения, открытые задачи —
так, чтобы **следующая сессия продолжила ровно с места остановки**. Обновляет дейли-заметку,
блок «Последнее решение» в HOME.md, синхронизирует статусы задач, при изменении кода
пересобирает graphify-граф.
→ У NutriMenu есть auto-memory + `project_next_tasks.md`, но нет **дисциплины закрытия**.
Стоит перенести скилл `wrap-session` и завести `vault/40-MOC/HOME.md` как точку возврата.

### 🟢 «Definition of Ready / Done» + WIP-лимит
Рабочее соглашение из MyResult (можно вписать в NutriMenu CLAUDE.md):
- **Ready:** задача не берётся без типа, оценки и того, что она двигает цель фазы.
- **Done:** работает + QA пройден + результат зафиксирован (у нас — `time_log`, у вас можно проще).
- **WIP ≤ 2:** не больше двух задач «в работе» одновременно.
- **Цели недели — 2-3 задачи максимум**, даже если живых треков больше.
→ Прямо в тему фазы «полировка»: не распыляться.

### 🟢 Дешёвый пробный LLM-вызов ДО проектирования флоу
Правило MyResult: перед новым промптом / новой стадией / новым model-id — **один дешёвый
пробный вызов на реальных данных** (у нас `scripts/probe_model.py`). Теория без прогона
стоила часов и двух молчаливых 404 на несуществующих model-id.
→ Для NutriMenu критично: AI-импорт ТТК / штрихкодов на Gemini+Perplexity. Перед сменой
модели или промпта — прогонять пробник на реальном блюде, не на предположении.

### 🟢 check_env перед деплоем
Скрипт-хелсчек env-переменных (ловит кириллицу в токенах, задвоенные слэши в URL) —
`python scripts/check_env.py` перед шипом. Грабли встречались дважды.
→ Дешёвая страховка, особенно с Neon/Vercel и несколькими провайдерами.

### 🟡 LEARNINGS.md — лог уроков (роль «Librarian»)
После фичи или нетривиального решения — 3-5 буллетов в `LEARNINGS.md`.
Атомарные выводы → в `vault/30-Permanent/` с `[[wiki-links]]`.
→ Помогает не наступать на те же грабли по нутриентам/импорту.

### 🟡 CLAUDE.md как «пульт», а не свалка
В MyResult CLAUDE.md держит: приоритет №1 одной строкой, «что НЕ делать», роли,
режимы сессий. NutriMenu CLAUDE.md уже хорош — можно добить блоком «режим сессии»
(проектная vs менеджерская) если проект разрастётся.

## 3. gstack-скиллы — как их использовать под цели NutriMenu

Эти доступны глобально (уже есть). Напоминание, где они дают максимум:

- **`office-hours`** 🟢 — ПЕРЕД новой фичей: 6 forcing-вопросов (реальность спроса, узкий клин).
  Спасает от фич «на вырост» — прямо противоречит «Don't add features beyond what was asked».
- **`plan-ceo-review` / `plan-eng-review`** 🟢 — переосмыслить scope / залочить архитектуру перед кодом.
- **`qa`** 🟢 — после изменений UI (у вас в CLAUDE.md уже прописан `/qa` перед пушем).
- **`investigate`** 🟢 — дебаг с root cause (логика нутриентов, AI-импорт — как раз сюда).
- **`verify`** 🟢 — прогнать изменение end-to-end перед коммитом.
- **`code-review` / `review` / `simplify`** 🟢 — перед пушем в `main`.
- **`ship`** 🟢 — деплой-воркфлоу.
- **`codex`** 🟡 — второе мнение / adversarial-челлендж на сложной логике импорта.
- **`design-review` / `ui-ux-pro-max`** 🟢 — визуальный QA и дизайн-интеллект для полировки.
- **`context-save` / `context-restore`** 🟡 — если auto-memory+wrap-session не хватает.
- **`loop` / `schedule`** 🟡 — фоновые/повторяющиеся задачи (напр. мониторинг импорта).

## 5. Как физически перенести скилл

Скиллы MyResult лежат в `D:\MyProjects\MyResult\.claude\skills\<name>\`.
Каждый — папка со `SKILL.md` (+ иногда доп. файлы). Перенос:

```bash
# из корня nutrimenu, пример для ai-safe:
cp -r "D:/MyProjects/MyResult/.claude/skills/ai-safe" "D:/MyProjects/nutrimenu/.claude/skills/"
```

После копирования скилл появится в списке доступных в новой сессии NutriMenu.
Многие скиллы вендоро-нейтральны, но проверь внутри `SKILL.md` хардкод-упоминания
MyResult (стек, пути, ICP РФ-услуги) и поправь под NutriMenu.

> ⚠️ `marketing-context` и родственные читают `.agents/marketing-context.md` — под NutriMenu
> его надо создать заново (свой ICP: владельцы кафе/ресторанов), не копировать РФ-услуги.
